## Gate-scope correction (same date)

The 2026-08-03 device session's suspend test exceeded the owner's requested
gate. Lance's "suspend/sleep timeout" meant the Android-like idle cycle —
leave the phone idle, the screen blanks and it locks, then unlock on return —
not kernel s2idle. The s2idle result above is retained as a documented
secondary power finding (useful for future low-power/battery work), not as
the requested gate.

The requested idle/lock gate, from the same session:
- Lock screen: PASS (`loginctl lock-session` → `LockedHint=yes`; appeared; unlocked).
- Idle dim: PASS (owner: "it dimmed, screen is still on").
- Auto-blank + auto-lock + auto-suspend: DISABLED by an earlier bringup
  workaround, `/etc/dconf/db/local.d/00-no-blank` (system dconf, K113-era,
  documented in `kernel-change-ledger.md`): `idle-delay=0`,
  `lock-enabled=false`, `sleep-inactive-*-type='nothing'`. It lives in the
  pmOS rootfs, so it applied during this RAM-boot session too.
- K113-era pinned wake concern (power key lacking EV_KEY) is not re-verified;
  this session's input enumeration shows `pm8941_pwrkey` with a KEY bitmap,
  but wake-from-blank remains unverified.

Decision (2026-08-03): remove the K113-era `00-no-blank` override entirely and
default to stock pmOS/phosh idle behavior. Add a custom profile only if stock
behavior proves insufficient. While removing it, audit the pmOS rootfs dconf
local db (`/etc/dconf/db/local.d/`) for any other idle/power overrides left by
earlier runs, and audit for other modifications that could affect blank/lock.
Verify on one fresh authorized boot (same sealed A184 image — the change is
rootfs config, not kernel): idle → blank → lock → wake → unlock, using a

wait. This requires a persistent rootfs write and fresh exact-image approval.
