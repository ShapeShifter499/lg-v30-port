## Fixed/decided

- REJECTED: continuous HS clock lane is NOT the fix. It regresses wake to
  no-re-enable at all. MIPI_DSI_CLOCK_NON_CONTINUOUS was load-bearing for
  the blank→wake path in this tree.
- Note the LockedHint=no on A187 vs lock engagement on A184–A186: the
  continuous-clock run also changed lock-on-blank behavior. The clock-lane
  setting interacts with the re-enable path more than the pure "turn-around
  corruption" hypothesis assumed.
- Remaining suspects (unranked until the next owner observation):
  - DPU/encoder first-kickoff gating on wake (flush/frame-done/TE) — the
    wake re-enable is the same path that A187 broke;
  - TE re-arm after display-on (SET_TEAR_ON re-send) — command-mode panel
    may need TE re-armed post-sleep-out;

  - DPU encoder enable ordering vs panel prepare (first frame after wake).
