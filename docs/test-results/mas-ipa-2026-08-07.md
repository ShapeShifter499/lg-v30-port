## 4. What changed and what was decided

### Fixed or changed

- `drivers/interconnect/qcom/msm8998.c`: mas_ipa `qos_mode INVALID → FIXED`, `qos_port = 1`, `areq_prio = 1`, `prio_level = 1`; `msm8998_a2noc_intf_clocks[]` gains `"ipa"` first; stale "no mainline IPA clock" comment corrected (the clock is `RPM_SMD_IPA_CLK` from rpmcc — it exists in `clk-smd-rpm`'s msm8998 table; an earlier search for it in gcc-msm8998 found only the `GCC_IPA_BCR` reset and wrongly concluded it did not exist).
- `arch/arm64/boot/dts/qcom/msm8998.dtsi`: a2noc node gains `<&rpmcc RPM_SMD_IPA_CLK>` / `"ipa"` first in clocks/clock-names, matching downstream fab-a2noc `qcom,node-qos-clks` order and the sdm660 binding pattern.
- `Documentation/devicetree/bindings/interconnect/qcom,msm8998.yaml`: new docs-only binding (a2noc requires ipa first; a1noc/mnoc fixed clock sets; bimc/cnoc/snoc none).
- Host config baseline: kernel builds now use the exact QoS-era config from `coding/build-qos-bimc-v2-24e82e84e/.config` (previously the July tree `.config` was missing `CONFIG_MSM_GPUCC_8998=y` and 60 other options).

### Decisions

- mas_ipa QoS accepted as FIXED/qport 1/prio 1,1 with the IPA clock enabled first — device-verified, upstream-candidate class.
- QoS coverage: **17/17 programmable masters** (35 total nodes; 17 ap_owned+programmable; `ap_owned` gate skips the rest).
- a2noc is no longer a "dark fabric": its intf_clocks are now exercised on every probe; mas_ipa was treated and proven as a fresh bring-up (one change, one boot, overlap scan first) — this discipline stays for any future first-time QoS fabric.
