# D-series: DSI frame-overhead investigation — closure — 2026-08-06

Device: LG V30 (joan), msm8998, SW43402 DSC QHD command-mode panel.
Goal: diagnose the owner-visible "fast but low fps" presentation
after CPU DVFS (C2C) and GPU (850 MHz) were verified working.

## What was measured (RAM-only boots, exact-image approvals)

- DSI link: FULL RATE — vco 1.3689 GHz, out_div 684.4 MHz (/2
  correct), byte0_clk_src 85.56 MHz, byte_intf divider 42.78 MHz
  (the K077 fix holds on device), pclk 114.07 MHz (DSC-correct).
- Frame timing (active-swipe drm.debug traces, kickoff->tx_done):
  median 30.3 ms; TE wait 0.1-0.3 ms (negligible); DSC 3:1 data at
  85.56 MB/s x 4 lanes is only ~4 ms — so ~26 ms/frame is a fixed
  transfer cost, insensitive to packetization.
- MDP core clock: 412.5 MHz = OPP table max (not throttled).
- GPU/CPU DVFS: working (257-850 MHz devfreq; schedutil scaling).

## Candidates tested and rejected (one variable per image)

| Candidate | Result | Evidence |
|---|---|---|
| D2 continuous DSI clock lane | REJECTED | blank/wake breaks (A187 regression reproduced; zero frames post-wake) |
| D3 MDP core clock | NOT THE BOTTLENECK | live 412.5 MHz = OPP max |
| D4 panel-shipped tuned PHY timings | REJECTED | 151.9 ms median (5x worse), link destabilized |
| D5 slice_per_pkt=2 (downstream config3) | REJECTED | 33.3 ms median, no gain; per-packet model dead |
| Host command-mode frame path audit | EXHAUSTED | every register byte-equivalent to downstream |

## Host-path audit summary

Mainline and downstream (android_kernel_lge_msm8998) agree on:
CMD_DMA_CTRL (FROM_FRAME_BUFFER|LOW_POWER, same effective offset
after DSI_6G_REG_SHIFT=4), TRIG_CTRL (TE + SW DMA + MDP none +
BLOCK_DMA_WITHIN_FRAME), CLKOUT_TIMING (t-clk-pre/post), burst
mode (CMD_MODE_MDP_CTRL2 BIT(16), joan traffic-mode=burst_mode),
DSC compression (2 encoders, DCS_LONG_WRITE, same slice layout),
MDP_DCS_CMD_CTRL (neither driver inserts 0x2C/0x3C on joan), PHY
timings, and clocks.

## Verdict

~30 fps is the measured command-mode presentation ceiling for this
bring-up: ~4 ms DSC data + ~26 ms panel-paced line-write acceptance
(~10.5 us/line), with every host-side configurable verified at
full-rate and byte-equivalent to the shipping Android stack.
Remaining explanations are panel-internal and not observable
without register-level instrumentation (STRICT_DEVMEM blocks
/dev/mem on the test image; no devmem tool).
